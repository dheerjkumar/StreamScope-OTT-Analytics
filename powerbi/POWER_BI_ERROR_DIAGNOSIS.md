## 2. Root Causes of All Three Errors

### ERROR A: "Failed to load the report" (PBIP opening)

**Root cause: Wrong PBIR Measure field syntax in all 22 visual.json files.**

Every visual that references a DAX measure used this structure:

```json
"field": {
  "Measure": {
    "Expression": {
      "Literal": { "Value": "[MeasureName]" }
    }
  }
}
```

This is **completely wrong**. The `Literal` wrapper is for static string constants in filter expressions, not for measure references. When Power BI Desktop tried to resolve `[MeasureName]` as a measure, it found no matching object in the semantic model and failed to load the report.

**Correct PBIR 2.15.0 syntax:**

```json
"field": {
  "Measure": {
    "Expression": { "SourceRef": { "Entity": "_Measures" } },
    "Property": "MeasureName"
  }
}
```

This syntax tells Power BI to look in the `_Measures` table for a measure named `MeasureName` — exactly what the semantic model contains.

### ERROR B: "Unable to open document – file is corrupted" (PBIX opening)

**Root cause: The .pbix binary was generated by a build script that packed the broken visual definitions.**

The `StreamScope_Analytics.pbix` (633 KB) was produced by `scripts/build_full_pbix.py` after the visuals were already broken. Because the internal DataModel inside the PBIX contained the same invalid `Literal`-wrapped measure references, Power BI Desktop rejected it as incompatible.

A PBIX file is a ZIP archive with a DataModel and a Report folder inside. When Power BI Desktop's internal engine cannot parse the visual definitions, it surfaces this as a generic "corrupted file" error.

**Fix:** Repair the PBIP project files first (done), then open the PBIP in Power BI Desktop and save as a new PBIX. Never generate a PBIX by ZIP-renaming.

### ERROR C: "Something's wrong with one or more fields" / "Select or drag fields"

**Root cause: Same Measure-Literal syntax error.** Power BI could partially open the report (the page tabs appeared) but could not bind any visual to actual data because all measure references resolved to nothing. This caused both:
- "Something's wrong with one or more fields" – when the visual had a queryState but the field resolved to null
- "Select or drag fields" – when the queryState was completely absent (some earlier iterations removed it entirely)

## 4. OneDrive Contribution

OneDrive synchronization was **not** a primary cause of the errors. All file sizes are consistent with fully-synchronized files (no truncated or zero-byte CSVs or JSON files). The `C:\StreamScope-OTT-Analytics` copy failed due to Windows sandbox write restrictions on `C:\`, not OneDrive locking.

The `.pbi/localSettings.json` contains a valid security binding signature — no sign of partial sync corruption.
